# NMC EdenGNN / R16 配对精度与耗时诊断

在 EdenGNN 最终测试之前固定本协议。范围为已有 0–7 共 8 个结构，每个 439,040 网格点，
沿用原 80/10/10 空间划分及验证选择子集。用户明确选择此范围；结果不代表未知结构泛化。

## 模型与训练

- R16：复用 `runs/nmc_probe_holdout_2026-10-26/r16_eight/best.pt`；原始 16,000 步、每步 1,024 点。
- EdenGNN：固定作者仓库 commit `3be8c06265c02ecf1ef0587500ee9b8e091186ef`，
  使用分发配置的 Encoder 和 DensityLayer（l=6，4 个径向输出通道），从头训练。
  官方类源代码不修改；通过 AST 只加载密度任务所需类，避免无关 PAW I/O 的 Fortran 依赖。
- 两者都使用原结构顺序与训练点 RNG、seed 42、Adam、归一化 L1、余弦学习率
  1e-3→1e-5、梯度裁剪 5、无 weight decay。EdenGNN 的训练更新与采样预算同 R16。
  这不是作者原论文全数据训练协议，参数量、架构和归纳偏置也不匹配。
- EdenGNN 的 Δ-density 起点由已有 POTCAR 原子 form-factor 脚本生成，无目标密度拟合。
  此起点尚未与 VASP 原生零步密度逐点核验，必须在报告中保留这一限制。
  此次不运行 PAW 占据预测或 VASP SCF，比较的是平滑网格密度。
- 训练使用官方原子中心、最近网格点取整的球形 stencil 的 CSR 视图，保留周期重数。
  每条边调用原版 DensityLayer.compute_chunk；必须在训练前核对与原版完整 forward
  的输出和所有参数梯度。不能将其悄悄换成以真实原子为中心的另一种 cutoff 算子。
- 只用原固定 8,192 验证点选择 checkpoint；先冻结 SHA256，再评估测试。
  保留全部采样审计、配置、源代码哈希。既有测试分区已经公开，因此描述性结果仍需独立数据确认。

## 评价与计时

- 精度：逐结构测试点 NMAE 后宏平均，同时给出训练/验证误差、电荷偏差及负密度量。
  不截断、不电荷重归一化。最终原生完整网格前向另作适配器一致性核验。
- 硬件：同一 RTX 5060 Ti；同一 PyTorch/CUDA，TF32 关闭；两者网络 float32。
  R16 白化重构沿用原 float64，作为模型实现的一部分如实列出，不强制降精度。
- 分别记录数据读取、SAD 准备、原子图、网格几何、主干、系数头、完整密度重构及设备传输。
  首次准备和复用几何后的热推理分开；端到端时间必须包含相应准备成本。
- 正式速度测试与训练串行，CUDA 显式同步，预热后重复测量；报告逐样本、中位数、P90 和峰值显存。
  模型加载不计入每结构推理，但单独记录。计时不把训练期预缓存免费当成新结构推理成本。
- EdenGNN 优先报告原版 DensityLayer.forward 的完整场时间，同时报告共同查询分块接口的耗时。
  算子细分为诊断用途，与无插桩总耗时分别测量，防止 profiler 开销污染正式结果。
- 本轮不按测试误差改架构或追加训练，不据单种子结果声称架构最优或统计显著性。

## 执行记录（测试前）

EdenGNN 从第 2,500 步检查点恢复后，训练主干使用 CUDA Graph 重放以减少 CPU 调度等待。
8 个结构各比较两次、跨优化器更新的输出与全参数梯度审核已通过（误差小于 1e-6）。
模型、损失、精度、优化器、采样 RNG 和 16,000 步预算不变；检查点之后未保存的更新丢弃并按原 RNG 重跑。
官方索引常量 [1,2,0] 在训练捕获前移到 GPU；没有修改官方类源文件。
正式推理计时在独立进程重新加载原版模型，使用 eager 执行。
审核记录及恢复检查点哈希见 `runs/edengnn_nmc_2026-10-28/execution_acceleration.json`。

附加诊断（Eden 测试前登记）：在基组、权重和 float64 精度不变的前提下，将 R16 白化矩阵及
scale^(-l) 提前作用到每原子系数上，逐点高斯包络只计算一次，并使用固定 65,536 边块。
该版本只作为代数重排的工程诊断，不替换主表中的当前 R16。输出和系数/坐标梯度单测已通过；
正式运行进一步检查完整网格相对误差及计时。原生输出作为数值参照，不按 DFT 测试误差选择实现。
